# Owner Chat / Work mode boundary — 2026-09-02

Status: **CURRENT OWNER-DIRECTED OPERATING RULE**

Joel's direct correction:

> `work mode is not used for thinking tasks, only for terminal work or very long-range bounded execution in github that chat oversees the reasoning of. most github work can be done in chat mode.`

## Required behavior

- Reasoning, editorial judgment, research synthesis, architecture decisions, prose writing, critique, evaluation, and owner interaction stay in the reasoning/writing Chat.
- Ordinary GitHub inspection, search, reads, comments, issue/PR work, and repository file edits should be done directly from Chat through the connected GitHub tooling when available.
- Do **not** hand off to Work merely because a task touches GitHub or requires persistence.
- Work mode is reserved for tasks that genuinely need terminal/computer-use/local execution, or for very long-range **bounded execution** where the reasoning Chat has already resolved the decisions, supplies the execution contract, and continues to supervise/interpret the results.
- Work is an executor, not the reasoning authority. It must not independently write or judge article prose, reinterpret owner corrections, invent task architecture, or take over the owner-facing reasoning loop.
- When Chat can perform the GitHub operation directly, prefer Chat.

This rule is cross-project operating guidance. Project-specific owner instructions may further narrow Work usage but should not silently broaden it into reasoning authority.
