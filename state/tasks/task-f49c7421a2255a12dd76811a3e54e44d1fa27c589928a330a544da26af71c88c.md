## Completed

- **`lib/task-checkpoint.ts` (new).**
  - It verifies a checkpoint named by repository, path, commit and SHA-256. It reads the file at that commit and checks its SHA-256. The JSON must name its `task` and a `base_commit`, and list 1 to 32 files with their SHA-256. Each listed file is read at the base commit and its SHA-256 checked. Size limits: 64 KiB for the checkpoint, 100 MB per file, 256 MB in total. Relative paths only.
  - It builds the verified review evidence (`verifier:task-checkpoint`, `INDEPENDENT`, the review-boundary refs). Its summary carries the checkpoint's statements, without its file list, up to 4,000 characters.
  - `registeredTaskHold`: a registered task whose latest decision has no bounded execution and no directive after it, plus the newest checkpoint verified after that decision.
- **`lib/github-repository-files.ts` (new).** Reads one file at an exact commit through GitHub's contents API with the raw media type, bounded in size and time. A 404 is a rejection; other failures are read errors.
- **`lib/github-app-auth.ts`.** An App installation token can ask for `contents: read` on one repository instead of issues; asking for both is refused.
- **`lib/task-checkpoint-record.ts` (new), `daemon/server.ts`.** `POST /workers/<worker>/task-checkpoints/verify` (owner only).
  - It reads only the task's repository from `MISSION_CONTROL_TASK_CHECKPOINT_REPOSITORIES_JSON`, and only for a registered task.
  - A rejection or read error records nothing. A checkpoint already verified is not read again.
  - A verified checkpoint for a held task makes that task's active watches due at once, with a due time no earlier tick used.
- **`lib/store.ts`.** `bringFleetSupervisorWatchesDue`.
- **`scripts/owner-action.ts`.** `checkpoint-verify --worker W --file F --commit C --sha256 S` (fixed shape, validated).
- **`lib/projection.ts`, `lib/owner-task-source.ts`, `lib/owner-view.ts`.** A held task's owner action is `OWNER.TASK_HELD_BY_SUPERVISOR`, shown as "Held by its supervisor" instead of missing telemetry.
- **`lib/fleet-supervisor.ts`.**
  - For a held task, an owner blocker still goes first. Otherwise:
    - with no newer checkpoint: `SUPERVISOR_HOLD` (notify the owner once, route nothing);
    - with a newer verified checkpoint: `CHECKPOINT_REVIEW_REQUIRED` (route quietly);
    - if that review was sent and expired unanswered: `OWNER_ACTION_REQUIRED` (notify, no re-route).
  - The review asks the supervisor to check the checkpoint against its decision. It then holds again with what is missing, or decides the first bounded step, with Work only where the contract allows it.
  - The factual state carries `held_by_decision` (the full decision, up to 2,500 characters). A review that doesn't fit shortens only the checkpoint summary, then the held decision, to no less than 500 characters each.
- **`lib/jev-shadow-telemetry.ts`.** Expectations for the two new triggers.
- **Docs.** README ("When its supervisor holds it, a verified checkpoint asks again"); `.env.example` (the repository setting).
- **Tests.** `tests/task-checkpoint.test.ts` (10), one `owner-action` test, one Jev telemetry test.
- **First independent review (of abfc2e47): one P1 and seven P2s.**
  - P1, fixed: a decision that asks the owner to decide (`owner_action` DECISION_REQUIRED, which a fleet decision can carry without bounded execution) was shown as a hold. It is no hold now, and keeps the projection's other rules.
  - P2, fixed: a tick already running when a checkpoint lands could commit its earlier hold and wait a day. Bringing a watch due now moves every active watch to a new unique due time, so the running tick can't commit.
  - P2, fixed: a checkpoint is refused (409) unless the task is held, so it can't become the boundary of a task that is executing.
  - P2, fixed: a review that can't fit one question even shortened no longer fails every poll. The check notifies the owner once and routes nothing.
  - P2, fixed: files are capped at 32 MB each and 128 MB in all. The README notes that a Git LFS file is read as its pointer text.
  - P2, fixed: a task that has had any directive is not treated as held (a later decision may continue a directive without new bounded execution).
  - P2, fixed: the tests use neutral placeholders instead of the live checkpoint's wording.
  - P2, fixed (laptop command): a second run compares with the counts from the first run's start, and the command stops early when the task isn't held or its watch isn't active.
