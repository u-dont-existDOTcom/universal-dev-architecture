## Completed

- **`lib/work-directive-expiry.ts` (new).**
  - `workDirectiveDeadline`: a native Work directive's deadline, from the validated decision receipt it was made from (null when none is known).
  - `expiredUnrunWorkDirective`: the latest directive, when it is an active v3 native Work directive whose deadline has passed and nothing crossed the provider boundary for it. A handoff intent without a result, any result other than an `UNAVAILABLE` one recorded before any Work call (`PRE_SEND_UNAVAILABLE_CODES`: `WORK_CLOUD_SURFACE_VERIFICATION_UNAVAILABLE`, `WORK_CLOUD_DISPATCH_UNAVAILABLE`, `WORK_CLOUD_DRIVER_BUSY`), a Work execution receipt, or a Codex start or receipt for the directive means it may have run, so it is not unrun. It also counts earlier unrun expiries since the last job that ran.
  - The expiry record: verified evidence from `verifier:work-directive-expiry` (`lifecycle_status:EXPIRED_UNRUN`, directive, revision, directive event, deadline, dispatch counts), one per directive event. `isBoundWorkDirectiveExpiry`: a record counts only when it names an existing directive event, carries that directive's expiry id, and was made at or after its deadline.
- **`lib/chatgpt-work-cloud-autodispatch.ts`.** Discovery skips a job not yet sent (`NEW`, `REQUEST_ONLY_PROVEN_UNSENT`) at or after its deadline; a `PENDING_SETUP` read-only check of a job already sent stays allowed.
- **`lib/store.ts`.** A native Work dispatch request (`requested_at`) and a handoff intent (`intent_at`) at or after the directive's deadline are refused.
- **`lib/fleet-supervisor.ts`.**
  - The classifier takes the tick's time. The question is only for a registered task (`expiredWorkJobForSupervision`). Every recorded owner obligation, any blocker on the owner or an outside actor (not only the latest one), and a missing contract source come first; only the projection's placeholder `OWNER.ACTION_TELEMETRY_MISSING` gives way (`expiryQuestionReplaces`). Unknown outcome advancement doesn't hold it back (registered tasks have no progress producer yet), and still applies after it.
  - The owner is notified and nothing is routed when: a second unrun expiry in a row; the question about the expiry was sent and went unanswered; an earlier question was sent and expired unanswered; or the question can't fit even with the prompt shortened (measured with the record routing would make). Otherwise `WORK_DIRECTIVE_EXPIRED_UNRUN` routes quietly. Once the supervisor has answered after the record, the expiry is settled.
  - Routing checks the expiry, retires an expired unsent earlier question if there is one, and only then records the expiry (once), which becomes the question's boundary, so the question is new.
  - The question's state carries `expired_work_job` (the record's refs) with `authorized_job`: `bounded_execution` (the expired decision's bounded execution in its own shape, so it can be authorized again as it stands) and `provenance` (request and decision ids, the bounded execution's digest, the prompt's SHA-256 and length, `prompt_clipped`). The prompt travels whole unless the question can't fit; then it is cut to no less than 500 characters, and the question asks the supervisor to write any prompt it authorizes out in full. The question asks to authorize the same bounded job again with a new deadline, change it, or stop, keeping the job's limits unless it says why.
- **`lib/task-checkpoint.ts`.** A registered task whose latest directive's job expired unrun is held again when the supervisor's answer after the expiry record starts no new step, so it waits for a checkpoint like any held task.
- **`lib/jev-shadow-telemetry.ts`.** The new trigger's expectation (`route_reasoning`, owner not expected to decide).
- **Docs.** README ("An authorized Work job that expired before it ran is asked about once"); `docs/CHATGPT-WORK-CLOUD-DISPATCH.md` (the deadline rule).
- **Tests.** `tests/work-directive-expiry.test.ts` (22). One fixture in `tests/chatgpt-work-cloud-autodispatcher.test.ts` moved its deadline from 2026-09-22 to 2099-09-22: that test dispatches at the real current time, so its old deadline now (correctly) stops it.
