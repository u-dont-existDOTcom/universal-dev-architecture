# Current State — Mission Control: the owner may retry a native Work start that failed at the ChatGPT app

## Goal

- Task ID: `pr-419`.
- Branch: `claude/mc-work-start-retry-20261022`.
- On 2026-10-22 the Atlas task's supervisor authorized a new Work job (open until 2026-10-24), and the dispatcher's start of it ended `UNAVAILABLE` (`WORK_CLOUD_PRODUCT_TOOL_EXECUTION_UNAVAILABLE`) (#385). The owner's read-only checks found the cause: the dispatcher's executor thread belonged to an earlier ChatGPT app, and Mission Control's own app refused every request from it. But the failed start is ambiguous by design, so nothing starts the job again: the dispatcher never re-creates under a recorded result, and the expiry question never counts such a job as unrun. This lets the owner authorize one retry, guarded by a read-only search for a Work thread of the failed start.
