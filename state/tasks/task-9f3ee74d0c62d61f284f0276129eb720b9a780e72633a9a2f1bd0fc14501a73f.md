## Completed

- **V6 rule (`lib/in-band-request-binding.ts`).**
  - The browser-DOM readback may come before or after the decision comment, because the copier records it first and posts second.
  - The readback follows the relay's recorded completion by ledger order, not by clock: the two times come from different hosts. The readback and the comment both precede ingestion (`created <= ingestedAt`). The removed ordering used to imply the completion check.
  - Unchanged: the readback must fall inside the request window; a comment created after the window needs app-owned evidence; an app readback beside a DOM readback is refused as ambiguous.
- **Copier (`lib/provider-decision-copier.ts`).**
  - Ingests with a time taken after the comment's immutable readback.
  - Records the relay readback right before its own post, after discovery, so a reconciliation can still take in the comment if the post's answer is lost.
  - Neither records a readback nor posts with less than two minutes of the request window left. The post can take its 30-second timeout, and a comment GitHub dates after the window can't be taken in. A comment posted inside the window is still found and ingested after it.
  - Discovery reads the decision issue only from 10 minutes before the request was queued (GitHub `since`), and keys matches by comment id.
  - An exact repeat of a copy still queued or running joins it. A repeat of an accepted decision reads back only the accepted comment (no discovery, no post) and is confirmed only for those exact bytes.
- **Worker page (`lib/projection.ts`, `lib/dashboard-data.ts`).** `projectWorkerById` projects only the requested task, with the whole-ledger relay context and Work-routing telemetry count. `GET /workers/:w` uses it.
- **Tests.**
  - `tests/in-band-request-binding.test.ts`: the copier's order is admitted; early ingestion, a readback before completion, a readback after the window and a comment after the window are refused.
  - An end-to-end test runs the real copier against the real V6 rule: one post, then ingestion, then a duplicate on replay. Both new tests fail on `main` with the production error.
  - `tests/provider-decision-copier.test.ts`: `since`, a shared in-flight copy, and the window guards.
  - `tests/dashboard-data.test.ts`: single-task projection equals the fleet entry; unlisted tasks give null.
- **Independent review** by a separate agent: no P0 or P1.
  - Addressed: ledger order instead of cross-host clocks; the readback and post windows taken back to back; the accepted-decision path without GitHub; de-duplicated matches.
  - The P2 is handled by the owner's command: answers wedged by the old rule would all be taken in after the deploy, however old. The command first lists every relay readback the copy step recorded, and stops before deploying if any besides the expected one is not taken in.
