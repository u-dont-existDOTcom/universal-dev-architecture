## Completed

- **Re-send logic (`lib/work-question-reissue.ts`).**
  - With `discardFinishedReply`, a sent question whose reply the relay saw finish (generation or session COMPLETE) is retired and re-sent, provided nothing read the reply back.
  - The retirement adds `finished_reply:DISCARDED_BY_OWNER` and `finished_reply_readback:NONE`. Its existing refs are unchanged, so it still counts and the old request stops being pending.
  - Any app-owned or browser-DOM readback, or digest-only transform, still refuses the re-send.
  - The result reports `finishedReplyDiscarded` (null for a repeat, which only reports the earlier re-send).
  - One shared list of readback summaries serves both the guard and the discard check.
- **Daemon route (`daemon/server.ts`).** `discard_finished_reply` must be a boolean; only `true` discards. Before a discard, the daemon runs one completed GitHub reconciliation pass of its own (`reconcileBeforeDiscard`): it waits out a pass already running, and stops on a failure or missing reconciliation (503, nothing retired). A reply already posted is therefore taken in rather than discarded. The re-send awaits this reconciliation only after its repeat check, so a repeat of a recorded re-send never waits for it. A discard without a reconciliation hook is refused.
- **Owner command (`scripts/owner-action.ts`).** `work-question-resend ... --discard-finished-reply yes`; any other value is refused.
- **Tests.**
  - `tests/work-question-reissue.test.ts`: discard with completion only; the retirement's refs, and that it still counts; readbacks and transforms still refuse; no change without a finished reply.
  - The async re-send with the discard: one batch, the discarding retirement, a repeat that appends nothing and asks for no new proof, and a readback alone still refusing.
  - The reconciliation before a discard: it waits for its own completed pass, and refuses when reconciliation is missing, fails or stays busy.
  - `tests/owner-action.test.ts`: the exact bodies, and the refused values.
- **Codex:**
  - P1: the reconciliation before a discard was only advice in the help text. The daemon now runs it itself.
  - P2: a repeat of a committed discard must not depend on reconciliation. The repeat check now comes first.
- **Independent review** by a separate agent: no P0 or P1.
