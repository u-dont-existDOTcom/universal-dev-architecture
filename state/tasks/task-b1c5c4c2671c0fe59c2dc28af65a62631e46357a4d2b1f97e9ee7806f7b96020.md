## Completed

- **Re-send logic (`lib/work-question-reissue.ts`).**
  - With `discardFinishedReply`, a sent question whose reply the relay saw finish (generation or session COMPLETE) is retired and re-sent, provided nothing read the reply back.
  - The retirement adds `finished_reply:DISCARDED_BY_OWNER` and `finished_reply_readback:NONE`. Its existing refs are unchanged, so it still counts and the old request stops being pending.
  - Any app-owned or browser-DOM readback, or digest-only transform, still refuses the re-send.
  - The result reports `finishedReplyDiscarded` (null for a repeat, which only reports the earlier re-send).
  - One shared list of readback summaries serves both the guard and the discard check.
- **Daemon route (`daemon/server.ts`).** `discard_finished_reply` must be a boolean; only `true` discards. Before a discard, the daemon runs one completed GitHub reconciliation pass of its own (`reconcileBeforeDiscard`): it waits out a pass already running, and stops on a failure or missing reconciliation (503, nothing retired). A reply already posted is therefore taken in rather than discarded. The re-send awaits this reconciliation after its repeat check and after the send proof, as the last await before the retirement, which it builds and appends synchronously. A repeat of a recorded re-send never waits for it, and a discard without a reconciliation hook is refused. The hook's last step reads the decision issue itself (`assertNoDecisionCommentFor`, from 10 minutes before the request was queued): any comment there naming the question stops the discard, because reconciliation may have read the issue before that reply was posted. The whole discard runs in Mission Control's decision-copy queue (`ProviderDecisionCopier.exclusive`): a copy already underway finishes first, so a reply it is copying is taken in and the discard then stops, and no copy starts until the retirement is appended.
- **Owner command (`scripts/owner-action.ts`).** `work-question-resend ... --discard-finished-reply yes`; any other value is refused.
- **Tests.**
  - `tests/work-question-reissue.test.ts`: discard with completion only; the retirement's refs, and that it still counts; readbacks and transforms still refuse; no change without a finished reply.
  - The async re-send with the discard: one batch, the discarding retirement, a repeat that appends nothing and asks for no new proof, and a readback alone still refusing.
  - The reconciliation before a discard: it waits for its own completed pass, and refuses when reconciliation is missing, fails or stays busy.
  - The final read of the decision issue: it sends `since`, pages through the issue, and refuses on a comment naming the question, on a read error, with no reader, or when the issue is too large to check.
  - A copier readback that lands while the discard reads GitHub stops the discard.
  - `tests/provider-decision-copier.test.ts`: an exclusive section waits for the copy in flight, holds later copies until it ends, and a failed section doesn't stop them. A source check pins the daemon's discard to that queue.
  - `tests/owner-action.test.ts`: the exact bodies, and the refused values.
- **Codex:**
  - P1: the reconciliation before a discard was only advice in the help text. The daemon now runs it itself.
  - P2: a repeat of a committed discard must not depend on reconciliation. The repeat check now comes first.
  - P1 (second round): the reconciliation is now the last await before the retirement, after the send proof, so a reply posted while the proof was read is still taken in.
  - P1 (third round): reconciliation awaits other reads after its decision-issue snapshot, so the discard now ends with its own read of the decision issue and refuses on any comment naming the question.
  - P1 (fourth round): Mission Control's copier could be mid-post while the discard read GitHub. The copier re-checks the request and records its readback in one synchronous step right before its post, so that discard already stopped on the readback. The discard now also runs in the copier's queue, so a copy underway finishes first and none starts during it.
