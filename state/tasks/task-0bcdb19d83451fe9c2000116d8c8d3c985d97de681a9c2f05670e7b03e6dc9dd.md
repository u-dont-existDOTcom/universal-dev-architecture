# Current State — Mission Control: a retry's search reads every turn of a thread before ruling it out

## Goal

- Task ID: `pr-422`.
- Branch: `claude/mc-retry-search-every-turn-20261022`.
- On 2026-10-22, before the Atlas task's retried Work start (#385, #419, #421), the controller's search for a thread of the failed start ruled threads out by their "first" user message. A read-only check of `read_thread` on the server showed its page is `"newest_first"`, with `nextCursor` and `hasMore` for older turns, and the thread's own `createdAt`. So the message compared was the newest one on the first page, not the first: a Work thread of the failed start with a later turn would have been ruled out, and the retry could have started the job twice.

## Completed

- `lib/chatgpt-work-cloud-controller.ts`: `searchForPrompt` reads each candidate page by page (`turnLimit` 10, then the page's cursor for older turns). Any user message on any page that is the prompt (or its 2,000-character readback) or holds a marker is a match. A thread is ruled out when its read shows it was made before the failed start (less the 10-minute skew), or when its last page says no older turns are left and it had at least one user message. A page that doesn't say whether older turns are left, or says so without a cursor, rules nothing out. Page reads count toward the 25 reads of a try. `PRIOR_SEARCH_RULE_VERSION` (2) names the rule.
- `scripts/dispatch-chatgpt-work-cloud.ts`: the rule's version is part of the saved progress's name, so threads ruled out under the old rule are read again.
- `tests/chatgpt-work-cloud-retry.test.ts`: a match on an older page; a thread ruled out only after its oldest page; one made before the failed start ruled out on one read; a match on the newest page; pages without paging information, or without a cursor, and threads without a user message rule nothing out. The test reads now carry a complete page.
