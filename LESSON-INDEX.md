## Promotion rule

Project-local evidence stays in the project repository. Promote a lesson here only when it is transferable beyond one project. Preserve the originating repository, source artifact, date/commit, rationale, and limits.

## Retrieval rule

Start with this index, then open only the relevant current pattern. Do not load every historical lesson indiscriminately. Newer owner correction and newer validated evidence supersede older conflicting guidance.

For long-running or multi-session project work, the project bootstrap/index should also point to one obvious current-state checkpoint (`CURRENT-STATE.md`, `state/CURRENT-STATE.md`, or an equivalent machine-readable file). A fresh worker must reconcile that checkpoint with actual Git state, independently recover the originating owner source rather than trusting a possibly narrowed checkpoint or worker handoff, report both alignment planes, report direct owner-outcome advancement and current strategy efficacy, and compare any proposed terminal state directly with the owner outcome before resuming or closing.

When a consequential task has an exclusive active-task lock, that branch-bound task identity and its preflight outrank unrelated handoffs, worktree checkpoints, autonomous roadmaps, and global next-task selection for that worker. Ordinary green tests remain prerequisites; the task-specific acceptance command defines readiness only for the boundary that acceptance command is designed to protect. It never substitutes for the root owner outcome or direct evidence that the chosen strategy is advancing it. If the owner explicitly changes the active goal back to rapid experimentation, update/supersede a stale release-grade task lock rather than treating it as permanently authoritative.
