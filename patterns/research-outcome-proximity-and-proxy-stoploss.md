# Research outcome proximity and proxy-work stop-loss

**Status:** Owner-required cross-project research control (2026-10-25).
**Trigger:** An owner wants an empirical answer, working result, or independent human/real-world validation, and a worker proposes another source audit, mock/synthetic data run, instrument rewrite, test suite, methodology layer, handoff or "continue" iteration.

**Problem:** Correctly executing a source-faithful plan and accumulating thousands of green engineering tests can still bring the owner **zero new evidence about the real question**. The **NON_UNIVERSAL / EXAMPLE_OWNER_DEPLOYMENT** G35–G39 Gene Keys sequence produced extensive chart-source audits, fake cohorts, simulated scores and six-language-style forms, while the owner wanted to know **whether astrology actually predicts something about unseen people**. The user later rated **23 of 24** questionnaire messages "very unnatural" and reported that the detour wasted time. The defect is not insufficient diligence: it is permitting preparation metrics to substitute for evidence, and automatically adding another preparatory subtask whenever the prior one succeeded.

This rule strengthens [outcome advancement and strategy efficacy](outcome-advancement-and-strategy-efficacy.md), [owner-goal follow-up and requirement accretion](owner-goal-followup-and-requirement-accretion.md), and [long-range research mission supervision](long-range-research-mission-supervision.md). Those remain normative. It does **not** repeal project-declared source fidelity, statistical blinding, software quality, participant consent or active-task locks.

## 1. Bind the literal testable owner outcome

Before a new long research work package or a "continue" response, preserve a three-line contract:

- **Target:** What observation would actually answer the owner's question? For an empirical prediction request, this is a frozen prospective claim compared with real, independent unseen responses, decoys and a meaningful nonastrology baseline—not a file count.
- **Current direct evidence:** Distinguish real independent observation count and findings from *source textual evidence*, simulation, unit tests, historical/development fitting, and speculation. A credible null or failure **is** valuable empirical progress. A green test alone **is not**.
- **Closest feasible next observation:** Who/what supplies it, whether the relevant cohort or data already exists, and the exact legitimate consent, access or method gap. Search for an existing suitable dataset or consenting participant route before inventing new infrastructure.

If the owner independently requested reading an entire historical book or constructing an apparatus, that document/text can itself be the target; do not wrongfully classify every source task as useless because it is not a human study. Preserve independent declared deliverables while rejecting *substitution* for a different owner goal.

## 2. Classify every proposed result before execution

Use one primary evidence class:

- `DIRECT_OUTCOME_EVIDENCE` — observation at the owner's intended real-world target, including a valid negative/null result, using the required cohort/independence.
- `NECESSARY_ENABLEMENT` — resolves a **specific demonstrated blocker** on the shortest path to direct evidence (e.g. unavoidable chart arithmetic or a consented-data schema). Record the exact test/observation it unlocks and why a smaller existing implementation is insufficient.
- `SOURCE_EVIDENCE` — improves fidelity/completeness of primary passages or data **when source coverage is itself requested** or a decisive missing source claim changes a near-term test.
- `SUPPORTING_QUALITY` — mocks, regressions, UI smoke tests, synthetic participants, repeated methodology or explanatory reports, when no direct source/outcome uncertainty is resolved.
- `ACCESS_OR_CONSENT_GATE` — legitimate external authorization, independent birth/response data, payment, source right or user/third-party action is missing. The next useful output is a bounded owner-ready handoff, not extra fake participants.

**Never aggregate classes.** Report counts separately. Tests may validate a parser, not empirical accuracy. A study with zero real people stays at **zero human validations**, whether 4 tests or 40,000 pass. Do not represent vague "closer to validation" or additional research branches as observed owner-outcome progress without identifying the changed independent gate.

## 3. Stop-loss at the next consequential continuation

When the owner outcome remains OPEN and supporting-only work has repeated:

1. **Review the last two material preparation-only iterations** (or an established shorter project budget) and compare the direct evidence state *before and after*. This is a **mandatory strategy-reassessment trigger**, **not** an arbitrary ban on doing valid work after exactly two steps. It does not override a source-critical project requirement.
2. Before another source/mock/instrument subtask, make the worker answer: **What previously impossible owner-relevant observation will this specific next step enable? Why not use the simplest existing method or ask for the actual required human data?** State the concrete new evidence, independent blockage and expected decision.
3. If no answer is supported, reject `ANOTHER_PROXY_ITERATION`. Preserve prior work, record its limitations and negative observations, then **pivot to the shortest feasible direct test or the exact human/access gate**; if another independent authorized lane can produce direct evidence, use it. Do not produce G40 merely because G39 finished.
4. If a newly identified, *material* engineering defect genuinely blocks a ready real test, permit a **single bounded source-bound repair**, with a **predeclared success signal** tied to that real test. Re-check at its end. Repeated repairs that still do not expose the real observation are not justified by the number of bugs fixed.
5. For absent participant consent, DOB/timezone or independently held outcomes, **never invent people, use a known biography as untouched, collect privately without permission, or borrow another active worker's cohort**. Save only the minimum usable consent/data handoff; say exactly which action requires a human. Do not replace this with more synthetic volunteers.
6. If a source's own rule is metaphorical, universal, nonexclusive or unfalsifiable, **do not invent a testable claim and attribute it to the author**. One bounded transparent `ANALYST_DERIVED` exploratory proposal is permissible, but fail to admit repeated instrument tuning as author-faithful predictive validation.

An explicit owner instruction to continue **source acquisition** or approve an optional experiment remains authoritative; state its evidence class. This rule is a stop-loss for *self-generated* work, not an excuse to obstruct authorized owner tasks.

## 4. Compact admission receipt and mechanical aid

At each material continuation, store or state (inline unless multi-session recovery requires a file):

```yaml
root_owner_target: "real independent chart->behavior predictive validation"
root_state: OPEN
direct_evidence_before: 0
direct_evidence_after: 0
last_supporting_only_cycles: 5
current_observation_ready: false
specific_blocker: "no independent consented untouched cohort"
proposed_action: "another 120 synthetic preference respondents"
proposed_evidence_class: SUPPORTING_QUALITY
material_new_real_test_unlocked: false
admission: REJECT_PROXY_LOOP
closest_next_action: "use authorized real forward-blind route; otherwise owner-ready consent/data gate"
owner_facing_summary: "0 real validations; 1 optional language instrument remains unvalidated"
```

The portable **`scripts/research_progress_admission.py`** can evaluate a minimal machine-readable continuation receipt and reject the specific *repeated proxy-work* class. Its decision is an **early warning/admission aid**, not an autonomous ethical consent oracle, a universal runtime interceptor, proof that a semantic proposed task is properly classified, or a new gate replacing project-specific requirements. For valid high-stakes/source-authorized tasks, missing source fidelity, study consent or safety controls are **never downgraded** by a green stop-loss result.

Do **not** add a new mandatory data schema or dashboard merely to implement this rule. A short natural-language evidence ledger is sufficient for a small research turn; use the CLI where a durable machine contract already exists.

## 5. NON_UNIVERSAL / EXAMPLE_OWNER_DEPLOYMENT — exact Gene Keys G35–G39 regression

**Reject:** The parent outcome is independent natal predictive validity. G35–G39 have **0 untouched human predictions**, at least five supporting/source iterations, hundreds of source/engineering tests and fake outcomes. A proposed G40 adds another randomized 200 synthetic respondents, new questionnaire UI and 50 new tests but does **not** unblock actual consent, source-specific interpretive specificity or independent real outcomes. Return `REJECT_PROXY_LOOP`; report direct progress **flat**, not advancing.

**Admit only with honest label:** An authorized source-book project explicitly asks for all 64 original public pages. Completing the 64 pages is `SOURCE_EVIDENCE` and directly meets the *source-audit* target, even without human validation. An independently required one-time boundary repair that unlocks an already-authorized real experiment is `NECESSARY_ENABLEMENT` if the exact blocker and simpler-route exclusion are documented.

**Human/data gate:** If all code necessary for the currently authorized test is ready but real independent birth records, consented responses or an external outcome custodian are absent, return `EXTERNAL_EVIDENCE_GATE` and prepare the shortest usable handoff; **do not** spin up another fake-recruitment/fixture chain. This gate does **not** grant contact, data access or study permission.

**Outcome admissible:** A consented truly unseen cohort with frozen predictions, real answers, valid decoy/baseline comparison and negative reporting yields `DIRECT_OUTCOME_EVIDENCE` whether it supports or falsifies the hypothesis.

## 6. Pre-final owner-facing summary

Say in plain language: **what we learned about the owner's real question; what is only source/engineering work; what failed or remains unknown; what actionable boundary comes next.** Do not headline cumulative unit-test counts ahead of scientific status. A correction from an owner (“was this a waste of time?”) must update strategy selection **in the same turn**, not simply create another preparatory "lesson" report.

**No universal prevention claim:** Adding the pattern, tests and routing can make this failure more detectable, but only actual task-time activation, correct evidence classification and subsequent observed behavior demonstrate that a consumer obeyed it.
