## Universal core

```text
REASONING SELECTION
Use the smallest sufficient combination of methods for the actual question, not its domain label. Answer simple tasks directly. Scale effort with stakes, uncertainty and reversibility. Distinguish exploration, decision, confirmation and release; apply heuristics only where their assumptions and the current phase fit.

Select by function:
- Analytic/formal: clarify definitions, decompose problems, check implications, constraints, calculations and invariants. Use tools for exact verification.
- Empirical/statistical/Bayesian: establish what evidence supports; assess source quality, base rates, effect sizes, uncertainty and competing evidence. Update proportionately; do not invent confidence percentages.
- Abductive/causal: generate plausible explanations, distinguish observation from mechanism, examine confounding and counterfactuals, and choose a test that discriminates alternatives.
- Systems/temporal: trace dependencies, incentives, feedback, delays, nonlinearities and second-order effects across relevant levels and timescales.
- Dialectical: investigate persistent conceptual or value tensions. Critique each position on its own terms; inspect shared assumptions and mutual dependence. Reframe when warranted; never force symmetry, compromise or synthesis, or reconcile an empirical falsehood.
- Phenomenological/interpretive: understand reported experience and meaning before explaining them. Keep observation, interpretation and causal claim distinct; do not impose a theory on the person or text.
- Generative/analogical: develop genuinely different possibilities before narrowing. Use analogy to generate hypotheses, not as proof. Preserve promising unconventional ideas without prematurely endorsing them.
- Decision/practical: compare realistic alternatives, including nonaction, against explicit goals, constraints, benefits, harms, ethical duties, opportunity costs and reversibility. Distinguish factual disputes from value choices. Seek further information only when it could change the decision, except where mandatory checks apply.

For consequential conclusions, test the strongest relevant objection or counterexample and verify load-bearing premises with sources, tools or discriminating tests. Agreement, fluency and repeated self-review are not independent evidence. Revise the model when warranted, not merely its wording. Report the conclusion, decisive support, material uncertainty and next action—not a ritual tour of methods. Separate facts, inferences, hypotheses and values; state disagreement directly. Follow current project authority and non-waivable gates. Before substantial bespoke design, preserve independent ideas when needed, scan existing work, choose reuse/adapt/compose/invent/experiment, and benchmark the remainder. Stop when the decision is supported or the unresolved uncertainty is explicitly bounded.
```

# Reasoning instructions — design and provenance

Version: 1.0, 2026-09-07.

## Use

Recommended: append the matching `*-standalone.txt` reasoning block to the project's existing instructions. Each contains the universal core, application boundary and one project-specific addendum. Do not paste the universal core a second time. Do not replace an existing bootstrap or canonical protocol with this block.

For a project already inheriting this exact universal core, use `project-application.txt` plus the matching `*-addon.txt` instead. These are a space-saving alternative, not extra layers to add to the standalone block.

`00-universal-core.txt` is the general-purpose version. All individual standalone blocks are checked against an 8,000-character design budget. Existing project instructions also consume the combined budget: count the whole field before saving. Never silently truncate existing authority or safety rules to fit this supplement.

Current repository instructions override the summaries here. Refresh the addenda when a canonical contract materially changes. This is a supplement for authorized reasoning chats, not permission for execution-only workers to originate strategies or policy.

## Existing-work disposition: COMPOSE

The pre-scan conception is recoverable from the conversation: use multiple reasoning methods selectively, with dialectics as a triggered checkpoint rather than a universal method; return conceptual proposals to empirical testing where applicable. This record does not claim that later wording or project mappings existed before the scan.

Established components: formal analysis, empirical inference, causal discrimination, systems engineering, interpretive inquiry, dialectical critique, creative generation and decision analysis. Reusable implementation principle: a small task-sensitive selector rather than a mandatory procession of techniques. Reused governance: the repositories' existing authority, evidence, preservation, assurance-lane and discovery/confirmation rules.

Partially solved: adaptive reasoning and evaluation methods can inform selection, but do not establish that this specific text improves these projects. Incompatible defaults: mandatory debate, forced synthesis, recursive self-critique without evidence, release-grade auditing of every reversible iteration, or generic freeze rules imposed on all discovery. ## Static review and limits

The text was reviewed against these failure probes: simple calculation should not trigger all methods; a false factual claim should not be synthesized with truth; opposing results require context comparison; therapy meaning is not proof of historical events; development evidence may shape a model but not independently confirm it; theory-blind coding remains protected in development; green worker tests cannot replace owner outcomes; and editing cannot silently soften the author's argument.

These are manual coverage checks, not observed model behavior. Mechanical checks cover complete core inclusion, one correct addendum per standalone file, character limits, UTF-8 integrity and ZIP contents.

Before promoting an efficacy claim, compare existing project instructions alone, existing instructions plus this core, and existing instructions plus the matching standalone supplement on matched representative tasks with identical tools and budgets. Use independently judged correctness/faithfulness, unauthorized-action failures, completion quality and unnecessary effort; withhold drafting rationale from the reviewer. Keep a held-out task set for confirmation after any prompt revisions. No model/API evaluation or paid call was run for this package. Such evaluation is not a prerequisite for delivering this reversible instruction candidate, and it must not bypass existing project spending or evaluation gates.
